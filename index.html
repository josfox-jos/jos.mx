The intention is the atom of AI.

.jos is an open format, two reference kernels and a conformance kit for AI work you can save, verify and run again on any agent, any platform, any machine.

A .jos document is JSON that declares an intention: what is intended, when it is done (success criteria) and what to avoid (guardrails and limits). A kernel checks it before it runs, verifies it after, and leaves a receipt per step and a hash-chained ledger per run. Media type application/vnd.jos+json.

Start in one minute

npx @josfox/jos verify      # runs the embedded hello.jos through the kernel: SYSTEM HEALTHY
npm install -g @josfox/jos
jos init hello              # writes hello.jos, a 2.0 atom validated by the kernel
jos run hello.jos           # the verdict of each criterion, the run id, a metrics line
jos ledger verify <run_>    # every hash recomputed, chain continuous, run ended

Python: pip install jos-core gives the same kernel, the same ids and the same ledger bytes. Exit codes everywhere: 0 done · 1 not done · 2 invalid · 3 blocked · 5 valid but unexecutable · 124 time limit.

What a .jos looks like

An atom with a budget, sealed by its hash. Its content id, art_41deb162…, is the SHA-256 of the canonical document; change one byte and the kernel refuses to run it (code 3).

{
  "jos": { "version": "2.0.0", "kind": "atom" },
  "id": "hello",
  "meta": { "name": "hello", "version": "1.0.0" },
  "intention": {
    "objective": "Say hello and prove it",
    "success_criteria": [ { "exit": 0 }, { "stdout_contains": "hello:ok" } ]
  },
  "guardrails": {
    "avoid": ["network", "writing files"],
    "limit": { "seconds": 10, "output_bytes": 65536, "tokens": 1000, "cost_usd": 0.01, "retries": 0 }
  },
  "security": { "permissions": ["engine:shell", "net:none"] },
  "execution": { "engine": "shell", "run": ["sh", "-c", "echo hello:ok"] },
  "integrity": { "hash": "sha256:41deb162c4a96d87acbdb10dc41f756b6bf2d1872f21024e443697739210db00" }
}

Atoms

One intention, one verifiable result: objective, criteria, limits, permissions, what to avoid.

Flows

Intentions composed with needs, with and as. A step can run as a shadow clone with its own budget and ledger.

Directories

A folder with .jos/manifest.jos is a document too. Limits only tighten and permissions only narrow from parent to child.

Receipts and ledgers

Every step leaves a receipt with each criterion's verdict and the hashes of input and output; every run an append-only, hash-chained ledger anyone can verify.

Validate a .jos in your browser

Structural checks of the 2.0 document model (header, metadata, intention, limits) and the content identity computed the way the kernels compute it: SHA-256 over the canonical JSON with integrity.hash and integrity.signature emptied. Nothing leaves your browser and nothing is executed.

Full validation against the JSON Schema and the conformance kit: jos validate <file> --strict.

The specification

The format, its JSON Schemas, conformance vectors and companions (JOSID, Ledger, Capability, Context engine) live in josfox-jos/jos-spec, the specification of the media type application/vnd.jos+json. Version 2.0.0 is an additive superset of 1.0.0. The conformance kit has 279 document vectors; the JavaScript and Python kernels pass all of them with identical results.

The earlier 0.0.7 draft is kept for history at josfox-ai/jos-format-spec; a 2.0 kernel still reads 0.0.7 documents.

Everything else, including what ships today and what does not yet, is in the main repository: josfox-jos/jos. Agents start at its llms.txt.
